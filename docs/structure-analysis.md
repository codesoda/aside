# Structural analysis

`aside.structure` inventories Rust entities from immutable, retained Git objects at the pinned pull-request HEAD. It reads changed blobs at the comparison base only to locate removed entities and LEFT-side anchors. No checkout, project build, model, network request, or new graph database is used. Git context acquisition is shared with history; network fetch remains separately opt-in.

The provider reports one informational finding per enumerated changed entity and one corpus finding. Evidence contains the typed entity result, direct callees, shortest reverse-dependent paths, snapshot SHA, source sites, unresolved reasons and coverage. `related_code` relations point to dependent entity IDs. File/entity coverage and corpus metadata distinguish analyzed from unavailable scope. Counts cover only resolved entities in the analyzed corpus; zero does not assert no external dependants. Removed entities have unavailable relationship counts because no base graph is built.

The provider supplies pinned root `Cargo.toml` bytes so the engine can validate conventional Cargo `src/lib.rs` or `src/main.rs` Rust module trees. Custom layouts, other languages, macros, glob imports, re-exports, dynamic/method dispatch, unsupported paths, ambiguous names, parse errors and out-of-corpus references are not inferred as links. Unavailable comparison-base objects preserve safe HEAD inventory but suppress complete relationship claims and deletion anchors. Unavailable HEAD objects or stale context produce partial results without structural claims. Truncated scans and unresolved sites are explicitly partial.

Default engine bounds: 1,000 Rust files (changed first), 512 KiB per blob, 500 entities per file, 200 visited entities and 20 paths per result, traversal depth 4, 250 ms parse budget and 200 entity results. The provider shares a 75-second deadline and has a 100-second scheduler timeout. Its result cap is also bounded by the configured `analysis.structure.max_findings` (one slot reserved for corpus metadata). Use `analysis.structure.enabled`, `analysis.structure.timeout_ms`, `analysis.structure.max_input_bytes`, `analysis.structure.max_input_files` and `analysis.structure.max_findings` as repository-scoped settings; refresh a session to apply changes. This is conservative review context, not a defect verdict or a complete cross-crate call graph.
